# Summary

Ali, 2026-10-22: when he runs OMR, the "Upload" status at the top right
starts at 100% and then sits there for a while with no progress shown.

# Diagnosis (inferred from the code, not measured)

`AppState.UploadProgressDelegate` reports `didSendBodyData`, which counts
bytes handed to the network stack, not bytes the server has received. A PDF
of a few MB is buffered almost at once, so the bar reads 100% immediately.
The wait that follows is `session.upload` waiting for the OMR service's 202,
still labelled "uploading…": the real transfer plus whatever the service does
before it answers, probably including a Cloud Run cold start on a service
capped at one instance.

# Done when

- The stage after the bytes are handed over says what is happening (for
  example "starting the converter…", indeterminate) instead of a full upload
  bar, until the 202 arrives.
- The wait is measured once against the live service on a real scan: how
  long the transfer takes, how long until the 202, and whether a cold start
  is most of it. If it is, say so in BACKLOG beside the OMR gateway work.
- A unit test holds the stage sequence (`MakeEditable` already decides how
  the converting stage reads).
